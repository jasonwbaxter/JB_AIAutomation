Jason Baxter’s Microsoft AI Field Guide · No. 10 · Training: IT and AI admins

Get the platform ready before the people arrive

A practical plan for IT and AI administrators. Fix access first, set guardrails and budgets, then give agents trusted data. Each session ends with a check you can show your security lead.

Audience: IT, security, data and AI adminsFormat: 6 sessions × 60 minTotal: 6 hours, before the user rollout

Before you start

  • AI Administrator, SharePoint and Purview admin roles assigned
  • A pilot group of 20–50 users
  • Auditing turned on in Microsoft Purview

How to run it

  • Follow Microsoft’s blueprint: fix oversharing, set guardrails, meet regulations
  • Pilot, then deploy, then operate
  • Review agents, costs and alerts every month

How you’ll know it worked

  • No high-risk site is open to everyone
  • Every agent has an owner and an approval path
  • Every paid service has a budget and an alert

Session 1

Apps, agents and MCP servers: what you now govern

60 min
Old way
Package apps with Intune, assign them to groups, and you’re done.
→
New way
Also govern agents in the Agent 365 registry: install, block, approve, assign owners, and control which tools and MCP servers they reach.
AppsIntune and the admin center, as today
AgentsAgent 365 registry: inventory, owners, approvals, blocks
MCP serversTools agents call; governed by data policies and tool controls

Why it matters

Agents act, so they need owners, approvals and limits like any user. MCP connectors in Copilot Studio fall under your Power Platform data policies. Agent 365 adds tenant-wide control of which tools agents can use.

Try it · 10 min

In the Microsoft 365 admin center, open Agents > All agents. Find ownerless agents, check the Requests tab, and block anything you don’t recognise.

✓ Done when

  • Every agent has a named owner
  • A documented path to request and approve an agent or MCP server

Session 2

From file shares to governed SharePoint

60 min
Old way
File shares, sites open to “Everyone except external users”, and sharing links that never expire.
→
New way
SharePoint sites with owners, sensitivity labels at creation, limited sharing links, and sensitive sites hidden from Copilot until they’re fixed.

Why it matters

Copilot shows people what they already have access to. Oversharing is the biggest Copilot risk, and it was already there before Copilot arrived. Clean structure also makes answers more accurate.

Try it · 10 min

Run the SharePoint Advanced Management content assessment. List the 10 most overshared sites, then turn on Restricted Content Discovery for the riskiest ones.

✓ Done when

  • High-risk sites have owners, labels and fixed sharing
  • Copilot no longer surfaces restricted content (check in Purview audit)

Session 3

Technical readiness and guardrails on every platform

60 min
Old way
Assign licences, switch Copilot on, and fix problems as users report them.
→
New way
Check readiness per platform, then set guardrails: sensitivity labels, Purview DLP for Copilot, Insider Risk, web search policy and auditing.
Windows and MacCurrent apps, Copilot app, new Outlook, Edge for Cowork browser tasks
iPad and iPhoneCopilot, Outlook, Teams and Office apps; some features are partial
AndroidCopilot and Teams; Word on phones is summary and chat only
LinuxWeb only: no Teams or Office desktop apps

Why it matters

Features differ by platform, so a user’s experience depends on their device. Guardrails protect sensitive data by default instead of relying on every user to get it right.

Try it · 10 min

Run the Copilot license details diagnostic for your pilot users. Create a DLP for Copilot policy that blocks files labelled Highly Confidential from grounding.

✓ Done when

  • A readiness checklist passed on each platform in use
  • Guardrails tested with a pilot user and verified in audit

Session 4

From shared-account bots to computer use you control

60 min
Old way
RPA bots on shared service accounts, with passwords in scripts and nobody sure what they touch.
→
New way
Cowork browser tasks run in the user’s own Edge with their own access. Unattended computer use runs on Windows 365 for Agents.

Why it matters

Computer use lets agents operate apps that have no API. Run it under a real identity, inside your existing Conditional Access and DLP rules, with approvals for sensitive actions.

Note: Cowork browsing is off by default and needs Microsoft Edge 152 or later.

Try it · 10 min

Turn on Cowork browser access for the pilot group only (Copilot > Settings > Cowork settings). Apply the Edge policy to managed devices.

✓ Done when

  • Browser tasks allowed for the pilot group only
  • Policy and approval rules documented

Session 5

Why AI costs skyrocket, and how to stop it

60 min
Old way
One licence price per user and no usage bill to watch.
→
New way
Usage-based Copilot Credits for Cowork, agents and pay-as-you-go, governed by spending policies, user limits and alerts.
Wrong modelDeep reasoning on simple tasks: slower and dearer
Runaway agentsAutonomous agents looping or calling too many tools
No budgetsSpend nobody watches until the invoice
No ownersNobody accountable per service or team

Why it matters

Costs jump when people use the most powerful model for everything, agents run without limits, and nobody sets budgets. A budget alert doesn’t stop billing: only disconnecting a service does.

Try it · 10 min

In Copilot > Cost management, create a spending policy for the pilot with a monthly limit and alerts at 50, 80 and 100 percent. Teach users to start on Auto.

✓ Done when

  • Every paid service has a policy, a budget and an owner
  • A monthly cost review is booked with finance

Session 6

From raw data to trusted intelligence

60 min
Old way
Dump data in a lake, point an agent at it, and hope the answers are right.
→
New way
Refine data through bronze, silver and gold layers, certify the gold, then describe the business in an ontology so agents use the same language and numbers.
BronzeRaw data as it arrived; restricted access
→
SilverCleaned, matched and de-duplicated
→
GoldCurated, certified, ready for reports and AI
→
OntologyBusiness terms, relationships and rules agents understand

Why it matters

Raw data has no meaning: duplicates, conflicting definitions and missing context give confident wrong answers. Gold data gives trusted numbers. An ontology (Fabric IQ) adds the meaning, so “customer” and “revenue” mean one thing for every agent.

Try it · 10 min

Pick one KPI. Trace it from the gold report back to its bronze source, endorse the gold semantic model as certified, and generate an ontology from it.

✓ Done when

  • Agents for that domain ground only on certified gold data
  • One shared definition for each key business term
